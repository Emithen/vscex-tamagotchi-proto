# Pixel Perfect 렌더링 시스템

이 문서는 Tamagotchi Webview의 픽셀 아트, UI, 애니메이션을 하나의 규칙으로 관리하기 위한 제품·기술 기획입니다. 단순히 `image-rendering: pixelated`를 적용하는 것이 아니라 논리 해상도, 정수 배율, 에셋 규격, 재생 시간, 검수 방법을 고정하는 것이 목표입니다.

## 비전

- GBA 시대를 연상시키는 컬러 픽셀 UI
- 32×32 캐릭터 프레임과 캐릭터당 최대 16색 팔레트
- 홈, 돌봄, 스테이지, 전투가 동일한 4px UI 격자를 사용
- 화면 크기와 디스플레이 배율이 달라져도 아트의 픽셀 경계 유지
- 키보드, 스크린리더, 고대비 테마, 모션 감소 설정 지원

## 현재 기준

| 항목          | 기준                       |
| ------------- | -------------------------- |
| 논리 화면     | 144×216px                  |
| 화면 배율     | 1×, 2×, 3× 정수 배율       |
| UI 기본 격자  | 4px                        |
| 기본 테두리   | 1px                        |
| 캐릭터 프레임 | 32×32px                    |
| 팔레트        | 캐릭터당 최대 16색         |
| 투명도        | 완전 투명 또는 완전 불투명 |
| 렌더링        | 보간 없음, 픽셀 격자 정렬  |

Webview가 288×448 CSS px 이상이면 2×, 432×664 CSS px 이상이면 3×를 사용합니다. 조건을 만족하지 못하면 1×를 유지하며 분수 배율을 사용하지 않습니다.

## 에셋 규격

```text
media/pixel/
├── manifests/    # 프레임, FPS, 반복, 기준점, 타격 시점
├── sprites/      # 캐릭터와 이펙트 스프라이트 시트
├── backgrounds/  # 홈과 스테이지 배경
├── fonts/        # 라이선스를 확인한 픽셀 폰트
└── palettes/     # 테마별 팔레트
```

스프라이트는 프레임 크기의 정수배 캔버스를 사용합니다. 매끄러운 필터, 색상 그라데이션, 반투명 경계는 허용하지 않습니다.

## 기본 애니메이션

| 상태    | 권장 프레임 | 재생   |
| ------- | ----------: | ------ |
| idle    |           4 | 반복   |
| blink   |           2 | 간헐적 |
| eat     |         4~6 | 1회    |
| happy   |           4 | 2회    |
| hungry  |         2~4 | 반복   |
| sleep   |           4 | 반복   |
| attack  |         4~6 | 1회    |
| hit     |         2~3 | 1회    |
| faint   |           4 | 유지   |
| victory |           4 | 반복   |

## 아키텍처 방향

```text
Extension Host
  펫 상태·전투 판정·영구 저장
              │ snapshot / action 메시지
              ▼
Webview App
  화면 상태·입력·애니메이션 재생
              │
              ├── PixelViewport
              ├── SpriteRenderer
              ├── AnimationController
              ├── Pixel UI Components
              └── Accessibility DOM
```

현재는 Extension Host가 상태 변경마다 Webview HTML 전체를 교체합니다. 애니메이션 재생이 본격화되면 HTML은 한 번만 로드하고 Extension Host가 상태 snapshot을 보내는 구조로 전환합니다.

## 구축 단계

### 1. 렌더링 기반

- [x] 144×216 논리 화면 생성
- [x] 1×, 2×, 3× 정수 배율 정의
- [x] 4px UI 격자와 픽셀 디자인 토큰 정의
- [x] 모션 감소와 키보드 포커스 기본 처리
- [ ] Canvas 기반 `SpriteRenderer`
- [ ] 정수 배율과 DPR 조합 실기기 검증

### 2. 에셋 파이프라인

- [ ] `media/pixel/` 디렉터리와 manifest 스키마
- [ ] 32×32 오리지널 펫 스프라이트
- [ ] 크기, 팔레트, 반투명 픽셀 자동 검사
- [ ] 에셋 문제를 한국어 오류로 보고

### 3. 홈과 돌봄

- [ ] idle, blink, eat, happy, hungry 애니메이션
- [ ] 픽셀 포만감 게이지와 버튼
- [ ] 상태 변경 중에 Webview를 재로드하지 않는 메시지 흐름

### 4. 전투

- [ ] 스테이지 배경과 캐릭터 기준점
- [ ] attack, hit, faint, victory 애니메이션
- [ ] 픽셀 HP 게이지, 데미지 숫자, 타격 효과
- [ ] 저장된 `startedAt`과 행동 시각으로 중간 재생 복원

### 5. 검수와 확장

- [ ] 독립 Webview 프리뷰 하니스
- [ ] 너비·DPR·테마·상태별 스크린샷
- [ ] Canvas 영역의 픽셀 diff
- [ ] Light, Dark, High Contrast 테마 검수
- [ ] 새 펫과 스테이지를 위한 템플릿

## 완료 조건

- 모든 스프라이트가 정수 배율로만 표시됨
- 화면 리사이즈에서 분수 픽셀과 레이아웃 흔들림이 없음
- 전투를 다시 열어도 같은 시각의 같은 프레임을 표시함
- 키보드와 스크린리더로 모든 핵심 기능을 사용할 수 있음
- 기준 스크린샷 검사와 에셋 규격 검사가 CI에서 통과함

## 위험과 결정 기록

- 현재 `1280×1280` 이미지는 안티앨리어싱과 그라데이션을 포함하므로 임시 에셋으로만 사용합니다.
- 한글 픽셀 폰트는 가독성과 라이선스를 확인한 후 도입합니다. 도입 전에는 VS Code 기본 폰트를 사용합니다.
- 실제 배포 전에 캐릭터 명칭과 아트 에셋의 IP 사용 범위를 별도로 검토합니다.
