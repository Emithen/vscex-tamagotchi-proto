# 로드맵

이 문서는 현재 구현 상태와 다음 작업 후보를 구분해 기록합니다. 예정 항목은 확정 일정이 아니라 우선순위 논의를 위한 제안입니다.

## 완료

- VS Code Activity Bar와 Tamagotchi Webview 등록
- 기본 펫 `물짱이` 표시
- 포만감 숫자와 진행 막대 표시
- 먹이 주기 버튼과 포만감 증가 처리
- 포만감 범위 제한 (`0~10`)
- VS Code `globalState`를 이용한 상태 저장
- 개발용 포만감 설정 명령
- 상태 로직 단위 테스트
- TypeScript, ESLint, Prettier 검증 명령
- `초원 1` 스테이지 선택과 자동전투 재생
- 공격력, 방어력, 속도를 사용한 전투 시뮬레이션
- VS Code `globalState`를 이용한 전투 재개와 보상 중복 방지
- 스테이지 ID, 이름, 적, 승리 보상 설정 분리
- Pixel Perfect 144×216 논리 화면과 정수 배율 렌더링 기반
- 4px 격자의 픽셀 UI 토큰과 모션 감소·키보드 포커스 기본 처리
- 32×32 오리지널 펫 idle 스프라이트와 Canvas 재생
- 픽셀 에셋 manifest와 크기·팔레트·투명도 자동 검사

### 시간에 따른 포만감 감소

감소 규칙은 다음과 같이 확정했습니다.

- 포만감은 1시간마다 1 감소
- `nextFullnessDecayAt`으로 다음 감소 시각을 포만감 전용 필드에 저장
- VS Code가 종료된 동안의 경과 시간도 다음 상태 조회 시 반영
- 1시간 미만의 남은 시간은 다음 계산에 유지
- 포만감은 0 아래로 감소하지 않음
- 최대 포만감에서 추가로 먹이를 줘도 감소 기준 시각을 연장하지 않음
- 개발 명령으로 포만감을 직접 설정하면 해당 시각부터 다시 계산
- 타이머는 화면 갱신에만 사용하고 실제 상태는 경과 시각으로 계산
- 현재 상태 스키마와 맞지 않는 개발 중 저장 데이터는 초기 상태로 덮어씀

- [x] 서비스 조회 및 먹이 주기 흐름에 감소 계산 연결
